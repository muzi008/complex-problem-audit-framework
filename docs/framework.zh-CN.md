# 复杂问题审计框架

> Complex Problem Audit Framework

[English](framework.en.md) | **简体中文** | [项目首页](../README.zh-CN.md)

**版本：** `v0.1.0-beta`  
**状态：** 公开测试版，尚未经过大规模用户验证  
**来源：** 从作者私人使用的《复杂问题回答框架 v2.6.1》派生  
**形式：** 模型无关的分析协议，可供人类、AI 或人机协作使用

## 适用范围与价值立场声明

本框架最初形成于作者的中文语境、个人长期实践，以及对中国普通人现实约束的持续观察。它不是价值中立的计算器，也不声称代表所有国家、民族、宗教、文化传统或政治制度的共同立场。

框架中的证据校准、权重与置信度分离、反方验证、推翻条件和不确定性标注，旨在提供可审计的分析程序。主体性保护、资源约束、主流叙事审计以及权力、利益与盲区分析，则包含作者明确选择的价值关注。

使用者可以根据当地法律、文化背景、宗教信念、社会关系和个人目标调整具体价值权重，但不应改变核心术语的定义、稳定编号和审计程序后，仍将结果称为同一版本。

当不同价值之间无法达成一致时，本框架不保证给出全球统一答案。它的作用是公开分歧、证据、代价、权重和推翻条件，让不同立场的结论能够被理解、比较和修正。

## 规范地位与语义稳定规则

中文框架是本项目的语义来源。英文版是受控翻译，不构成独立框架。发生歧义时，应结合稳定编号、中文定义、必须项和禁止项裁定，不能只凭某个英文单词重新解释模块。

4. 不同 AI 的措辞和结论可以不同，但必须遵守相同定义、必填字段、证据标记和质检条件。
5. 使用者修改核心定义后，应将结果标记为派生版本，不得继续声称完全符合原版本。

## 一句话定义

一套用于分析复杂问题的模块化框架。它要求使用者同时检查问题边界、价值锚点、证据可信度、反方、利益关系、不确定性、资源约束和现实行动，避免把信息堆积误当成判断。

## 为什么需要它

复杂问题常见的失败，不是信息太少，而是以下几件事被混在了一起：

- 重要的信息不一定可信；
- 可信的信息不一定决定结论；
- 事实、推断和价值选择没有分开；
- 某一方的目标被伪装成唯一标准；
- 理论上正确的方案，在现实资源下无法执行；
- 回答列了许多角度，却没有说明什么会推翻结论。

本框架试图把这些环节拆开，让结论能够被检查、修正和复用。

## 设计立场

本框架不是价值中立的计算器。它公开承认以下立场：

1. 证据质量比表达气势更重要。
2. “重要程度”和“可信程度”必须分开判断。
3. 价值排序应被说明，不能伪装成天然客观。
4. 分析应检查谁在定义问题、谁获益、谁承担代价、什么被忽略。
5. 行动建议必须考虑金钱、时间、试错空间、执行阻力和不可逆风险。
6. 效率不是唯一价值，人的尊严、关系、生活质量和长期主体性不应自动让位于效率。
7. 使用者可以调整价值锚点，但必须公开说明调整后的依据和代价。

这些立场构成框架的特色，不被包装成适用于所有人的唯一答案。

## 适用范围

适合：

- 职业选择与能力迁移；
- 教育、家庭和长期关系问题；
- 企业、组织与 AI 转型决策；
- 公共政策、社会结构和多方利益冲突；
- 高不确定、长期、不可逆或代价较高的选择；
- 需要审查证据、叙事、风险与行动条件的问题。

不适合直接使用：

- 简单事实查询；
- 基础计算和明确操作步骤；
- 紧急医疗处置；
- 需要执业资格才能作出的诊断、法律意见或投资承诺；
- 缺少关键数据、实验或现场检查时仍要求确定答案的问题。

高风险领域可以使用本框架整理问题和证据，但不能替代医生、律师、注册会计师、持牌金融人员或其他合格专业人士。

## 核心流程

```text
SQ -> DF -> ST -> WA -> EV -> CT -> UN -> AC -> AU -> CN
```

- **SQ（Scope Question，范围锁定）**：本次讨论什么，不讨论什么。
- **DF（Define，定义校准）**：关键词、事实口径和隐藏前提是什么。
- **ST（Stakeholders，视角地图）**：谁参与、谁受影响、各自目标是什么。
- **WA（Weight Anchor，权重锚点）**：什么因素最应决定本题结论。
- **EV（Evidence，证据校准）**：证据是否可靠、直接、及时并可交叉验证。
- **CT（Counter-test，反方检验）**：最强反方是什么，什么会推翻当前判断。
- **UN（Uncertainty，不确定性）**：概率、未知项、时空差异和尾部风险是什么。
- **AC（Action，行动适配）**：在真实资源下，什么行动可做、可逆、可验证。
- **AU（Audit，审计）**：权力、利益、盲区、来源偏差和 AI 偏差在哪里。
- **CN（Conclusion，结论）**：给出阶段性结论、适用边界和更新条件。

流程不是固定作文模板。简单问题只启用少量模块，重大问题才进入完整审计。

## 三种使用模式

| 模式 | 适用情况 | 最低输出 |
|---|---|---|
| Quick | 范围清楚、风险较低 | SQ、DF、EV、CN |
| Standard | 多因素判断或现实选择 | SQ、DF、WA、EV、CT、AC、CN |
| Full Audit | 高风险、长期、多方冲突、不可逆 | 全部模块 |

如果使用者追加条件，不必重写全文。只需说明：

- 哪些结论不变；
- 哪些结论需要修改；
- 新条件改变了哪个锚点、证据或约束；
- 更新后的结论是什么。

## 模块一：范围与定义

回答前先写清：

| 项目 | 要回答的问题 |
|---|---|
| 时间范围 | 讨论当下、过去成因，还是长期趋势？ |
| 空间范围 | 适用于哪个国家、地区、行业、组织或家庭？ |
| 人群范围 | 谁是主要当事人，谁会承担后果？ |
| 决策目标 | 是理解、选择、降低风险，还是采取行动？ |
| 排除项 | 哪些问题暂不纳入？ |
| 隐藏前提 | 哪些条件被默认成立，却没有证据？ |

概念校准至少区分：

- 事实：目前能够核实的情况；
- 推断：根据事实作出的解释；
- 预测：对未来路径的条件性判断；
- 价值选择：什么结果更重要；
- 行动建议：在约束下应该做什么。

## 模块二：视角与价值目标

复杂问题通常不只有一个“正确视角”。至少检查：

- 直接当事人；
- 受影响但缺少表达权的人；
- 机构、平台或管理者；
- 研究者和专业人员；
- 法律与公共利益；
- 使用者本人声明的目标和约束。

每个视角回答四个问题：

1. 它最想保护什么？
2. 它愿意牺牲什么？
3. 它掌握什么信息？
4. 它最容易忽略什么？

视角地图用于发现差异，不要求把所有立场平均对待。证据更强、承担后果更直接、权利受影响更大的视角，可以获得更高权重，但必须说明理由。

## 模块三：最高权重锚点

先确定本题最应作为判断基准的因素，再讨论其他因素与它的距离。

常见锚点示例：

| 问题类型 | 可能的最高权重锚点 |
|---|---|
| 职业选择 | 长期可迁移能力、可承担风险、现实验证机会 |
| 教育问题 | 学习者的长期真实后果 |
| 亲密关系 | 安全、尊重、可持续的关系质量 |
| 法律风险 | 证据边界、程序和可承担后果 |
| 投资决策 | 资金安全、风险暴露和损失承受力 |
| AI 工具 | 稳定可用性、数据边界和工作流适配 |
| 公共政策 | 真实效果、分配后果和纠错能力 |

锚点不是永恒答案。必须回答：

- 为什么它在本题中最高？
- 谁会不同意？
- 如果换一个锚点，结论会怎样变化？

其他因素按相对距离描述：

- 核心：几乎与锚点同等重要；
- 接近：会明显改变结论；
- 次级：影响方案，不决定方向；
- 背景：用于解释，不直接决定结论。

除非有可靠数据支持，不用孤立的 `1-5` 分制造精确假象。

## 模块四：证据与置信度

权重回答“它有多重要”，置信度回答“我们有多相信它”。两者不能互相代替。

每条关键证据检查：

| 维度 | 检查问题 |
|---|---|
| 来源 | 是原始资料、官方文件、研究、媒体、平台讨论还是个人经验？ |
| 直接性 | 它直接观察了目标，还是经过多层转述？ |
| 一致性 | 是否有独立来源相互支持？ |
| 精确性 | 定义、样本、时间、地区和测量方法是否清楚？ |
| 时效性 | 信息是否已经过期？ |
| 利益相关 | 来源会因某种结论获益吗？ |
| 反方解释 | 同一证据是否存在合理的其他解释？ |

置信度使用高、中、低，并写出原因。不要只给标签。

### 高权重、低置信警报

如果一条信息会决定结论，但证据不足，必须标记为：

> **关键待验证项：当前权重高，但置信度不足，不能单独支撑强结论。**

随后说明需要补什么证据，以及在验证前采用什么临时方案。

## 模块五：正反检验与灰度

完整分析至少包含：

1. 支持当前结论的证据链；
2. 最强反方，而不是容易击败的稻草人；
3. 反方属于推翻、强修正、弱修正、视角差异还是纯情绪反对；
4. 正反之外的条件差异；
5. 明确的推翻条件。

建议使用以下表格：

| 项目 | 内容 |
|---|---|
| 当前判断 | 现阶段最合理的结论 |
| 最强支持 | 最能支撑它的证据和机制 |
| 最强反方 | 最有能力改变结论的反对意见 |
| 推翻条件 | 出现什么事实后必须改判 |
| 适用边界 | 在哪些地区、人群、时间或资源条件下不适用 |

### 敏感性测试

至少检查两个问题：

- 如果最高权重锚点改变，结论是否坍塌？
- 如果删除低置信证据，结论是否仍然成立？

## 模块六：权力、利益与盲区

复杂社会问题、组织问题和公共叙事默认检查：

| 问题 | 目的 |
|---|---|
| 谁在定义问题？ | 找出话语权和指标制定者 |
| 谁从当前解释中获益？ | 找出激励和利益关系 |
| 谁承担成本与风险？ | 找出被转移或隐藏的代价 |
| 什么被忽略？ | 找出统计、制度或传播盲区 |
| 是否把结构问题个体化？ | 防止把制度风险说成个人不努力 |
| 是否把少数人路径包装成普遍标准？ | 防止用高资源方案要求所有人 |

这个模块不是为了预设阴谋，也不是为了自动反对机构。它要求把权力和利益当作需要检查的变量，而不是预先写好的结论。

## 模块七：概率、时间与二阶效应

风险判断采用概率和影响分开表达：

| 类型 | 处理方式 |
|---|---|
| 高概率、高影响 | 优先处理 |
| 高概率、低影响 | 建立低成本管理措施 |
| 低概率、高影响 | 设置防火墙、保险或退出机制 |
| 低概率、低影响 | 不占用过多注意力 |

尽量说明：

- 当前概率是高、中、低，还是无法判断；
- 趋势在上升、下降，还是没有足够证据；
- 哪个信号意味着判断需要更新；
- 最坏结果是否可逆、可承受。

二阶效应只在政策、教育、长期关系、职业路径、AI 工具、组织管理和高风险行动中启用。每个推演必须标注：

- 时间尺度；
- 成立条件；
- 置信度；
- 哪些反馈会让结果反转。

不要把遥远的连锁后果写成必然。

## 模块八：行动、资源与执行阻力

先把变量分成四类：

- 无法改变，但需要知道；
- 投入大、收益低；
- 小投入、高回报；
- 会改变路径的关键转折点。

行动方案按问题本身选择时间尺度。默认可以使用：

| 时间 | 目标 |
|---|---|
| 立即行动 | 降低风险、补关键证据、停止不可逆损失 |
| 小周期验证 | 用低成本试验检验关键假设 |
| 长期积累 | 建立能力、资源、关系或退出选择 |
| 不建议做 | 明确高风险、低回报或不可逆行为 |

每项行动标注：

- 时间成本；
- 金钱成本；
- 试错成本；
- 可逆性；
- 对他人的影响；
- 失败后的退出方式。

资源版本使用高、中、低约束描述，不把特定阶层标签当成固定能力判断。

执行阻力不能被简化成“缺乏自律”。检查：

- 信息和技能是否不足；
- 启动成本是否过高；
- 家庭、组织或同伴压力是什么；
- 短期痛苦是否远高于延迟收益；
- 环境是否持续奖励错误行为；
- 能否用默认选项、试运行、外部支持或降低规模来改善执行。

## 模块九：主体性保护

在结构约束很强的问题中，仍要回答：

- 哪些变量确实无法由个人改变？
- 哪些局部选择仍能增加主动权？
- 什么不应完全被工具化？
- 哪些低效率价值仍值得保留？
- 如何避免把结构分析变成虚无主义借口？
- 哪些行动能增加未来的选择，而不是只解决眼前指标？

主体性保护不是积极口号。它要求区分真实限制与仍可行动的空间。

## 模块十：AI 偏差自检

当 AI 参与分析时，简要检查两到四项：

- 是否偏向公开可检索、英语或机构化资料；
- 是否为了合规而过度保守；
- 是否为了显得平衡而制造虚假对称；
- 是否把技术方案放在人的目标之前；
- 是否把多数人经验误当成当前使用者的处境；
- 是否因训练数据陈旧而错过近期变化。

自检用于暴露限制，不是固定的免责声明段落。

## 简短示例：是否应该换赛道

**原始问题：** 我在当前岗位发展一般，是否应该换一个热门赛道？

**问题重构：** 真正要判断的不是“哪个赛道热门”，而是现有能力能否迁移、目标市场是否愿意付费、试错成本是否可承担，以及是否能在离职前取得低成本验证。

**最高权重锚点：** 可验证的能力迁移，而不是赛道热度。

**关键待验证项：** 目标岗位是否认可当前经验。它权重高，但不能靠个人感觉判断，需要职位描述、从业者访谈、小型交付物或面试反馈。

**最强反方：** 如果当前行业正在快速收缩，等待完整验证可能错过窗口。此时应提高时间风险的相对权重。

**低成本行动：**

1. 从十个真实职位中提取重复能力要求；
2. 用当前能力完成一个目标岗位风格的小作品；
3. 找三名从业者验证作品与岗位要求的距离；
4. 在获得外部信号前，不把裸辞当成默认起点。

**推翻条件：** 如果目标行业职位数量、薪酬或进入门槛与预期不符，或者试做后发现核心工作内容并不适合，应修改或放弃转向方案。

**一句话归纳：** 不要从热门赛道出发赌未来，先用小成本证据验证自己的能力能否迁移过去。

## 已知限制

1. 当前版本主要来自长期个人实践和人机协作，尚未经过大规模对照实验。
2. 框架中的许多模块借鉴了决策科学、证据评估、系统思维、风险管理和利益相关者分析。原创贡献主要在选择、组合、顺序、接口与使用规则，不声称每个模块都是原创理论。
3. “最高权重锚点”和“相对权重距离”仍依赖判断者的价值选择，不能自动消除偏见。
4. 更长的分析不一定更好。模块过多会增加认知负担，因此必须使用动态路由。
5. 框架可以提高分析的可检查性，不能保证结论正确。
6. 框架不能替代缺失的数据、实地调查、实验、执业判断或当事人的最终决定。

## 公开版与私人原版的关系

公开 Beta 从私人版 `v2.6.1` 派生，但两者用途不同：

| 私人原版 | GitHub 公开 Beta |
|---|---|
| 面向作者自己的 AI 协作习惯 | 面向不同使用者和不同模型 |
| 包含本地归档与视觉交付流程 | 只保留分析与审计方法 |
| 固定个人审美和工具习惯 | 将呈现方式留给使用者选择 |
| 强调完整收束与无回归 | 强调按问题复杂度动态路由 |
| 使用个人语境中的触发词 | 使用通用调用方式 |

公开版不是对私人原版的覆盖或升级。私人原版继续独立保存。

## Beta 阶段希望验证什么

- 不同使用者能否理解“权重”和“置信度”的区别；
- 动态路由是否能减少模块堆积；
- 最高权重锚点是否能让结论更清楚；
- 反方、推翻条件和关键待验证项是否真的改变决策；
- 框架是否在职业、组织、教育和公共议题中保持可迁移性；
- 哪些模块重复、无效或容易被误用。
