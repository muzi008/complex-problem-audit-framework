# 复杂问题审计框架（CPAF）

[English](README.md) | **简体中文**

> 一套用于回答和审计复杂问题的自适应规则。先让短 CORE 形成可用答案，只有确实缺少证据、变量、竞争解释、鉴别测试或行动边界时，才增加分析。

- **公开版本：** v1.0.1
- **规范版本：** 复杂问题回答框架 v3.0.1 Final
- **发布日期：** 2026-08-14
- **状态：** 正式公开版，采用 CC BY 4.0；效果证据仍有限

## 它解决什么问题

复杂回答常见两种失败。

第一种是漏。事实、推断和价值混在一起，忽略最强反方，建议没有考虑风险、资源和执行阻力。

第二种是堆。为了表现严谨，把检查表、插件名、置信百分比和推理回执全部写给用户。信息更多，判断反而更难用。

CPAF v1.0.1 的默认假设很简单：

> CORE 已经足够。任何额外分析都要说明，不做它会损失什么。

如果继续分析不会改变结论、证据需求或行动排序，就停止。

## 一个文件，一套版本

项目只把 [docs/framework.zh-CN.md](docs/framework.zh-CN.md) 当作权威规范。

CORE-3.0.1、ADAPTIVE-3.0.1、Router 和 Plugins 是这份规范内部的运行层，不是四套并行版本。prompts/ 中的短文件只是从完整规范提取的运行摘录，可以重新生成，不得反过来改写规范含义。

普通问答不应把 2600 多行完整规范全部塞进工作上下文。完整文件用于阅读、审计、维护和评测；实际回答默认使用短 CORE，发现明确缺口后再进入 Adaptive。

## 最短使用方法

把 [中文运行提示词](prompts/cpaf.zh-CN.md) 作为系统规则或项目指令，然后直接提问。

它会要求模型：

- 先确认真正问题与用户已经知道什么；
- 区分事实、推断、假设、价值和行动；
- 在适用时比较主解释与最强竞争解释；
- 让外部证据真正更新判断；
- 让建议适配资源、风险、可逆性和执行阻力；
- 在边际价值归零时停止。

内部的 K/Q/E/M/F、插件列表、Router 日志、结论强度标签和未校准置信百分比默认不展示。

## v1.0.0 相比公开预览版

旧版 v0.1.0-beta 是 2026-07-17 发布的公开原型，主要用于说明审计维度。它已保留在 Git 标签和历史提交中。

v1.0.0 改成分层运行：

- 短 CORE 默认作答；
- Adaptive 只修复已指明的缺口；
- 插件数量允许为 0，每张插件卡都要证明可观察增量；
- 工具和自由探索按证据义务触发；
- 审计过程默认内隐；
- 加入删卡、停止和失败关闭规则；
- 把评测与版本治理写进同一份规范。

这属于公开接口的大版本升级，不保证旧提示词逐字兼容。迁移说明见 [MIGRATION.md](MIGRATION.md)。

## 已有测试

2026-08-13 完成了 10 道题、5 种条件、共 50 份匿名答案的同批次盲测。

| 条件 | 平均前台字符 | 相对 v2 FULL |
|---|---:|---:|
| 裸答 | 2,076 | 71% |
| v2.7.2.1 FULL | 2,906 | 100% |
| v3 CORE | 1,852 | 64% |
| v3 CORE + 人工方法卡 | 1,976 | 68% |
| v3 Adaptive Router | 1,905 | 66% |

50 份生成全部完成，正式答案失败 0，上下文隔离失败 0。盲评没有观察到与篇幅下降相对应的系统性质量损失，过重答案主要集中于 v2 FULL。

这批数据不能证明 CPAF 明显优于裸模型，也没有单独隔离 Tool Contract 或 Free Search 的效果。每题每条件只生成一次；模型由 UI 声明为 gpt-5.6-sol / high，程序无法核验，运行时还收到模型目录变化通知。完整限制与 Router 数据见 [测试报告](reports/v1.0-blind-evaluation.zh-CN.md)。

## 限制

- 框架改善的是回答纪律和可审计性，不能制造缺失证据，也不能保证结论正确。
- 当前证据来自小规模、单次生成的内部盲测，不是大样本独立验证。
- 医疗、法律、金融和安全等高风险问题仍需当地合格专业人士。
- 中文完整规范是语义来源；英文文件目前是参考概览，不是逐条受控翻译。
